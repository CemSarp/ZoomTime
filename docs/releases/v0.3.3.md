ZoomTime 0.3.3 fixes the guest pairing error `Unexpected token 'T', "The Tailsc"… is not valid JSON`. The failure came from Tailscale CLI status parsing before invitation validation, not from an identified invalid pairing token.

## What's fixed

- Guests can import an invitation when Tailscale command-line status is unavailable, non-JSON or structurally invalid. Open Tailscale and connect in its GUI if automatic connection is unavailable. The actual private WSS connection still requires normal TLS verification and authentication; fallback never claims that the VPN or host is online.
- Automatic hosting remains strict and reports an actionable, redacted error if CLI status is unavailable. Existing Serve services, grants and security settings are unchanged. Supported stopped sessions still connect automatically.
- The invitation is captured from the clipboard before opening another app, so later clipboard changes cannot replace the intended invitation during asynchronous setup.

The existing 0.3.2 host remains compatible. Only the guest needs this patch to resolve the import error; no pairing reset is needed solely for this error. Copy the complete invitation using the host's **Copy invitation**, not just its token field.
